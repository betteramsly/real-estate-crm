# Real Estate CRM — Спецификация MVP

## 1. Назначение Продукта

CRM для риелтора и небольшого агентства недвижимости. Позволяет вести клиентов, объекты, сделки и задачи в одном интерфейсе вместо разрозненных таблиц, чатов и заметок.

### Целевая Аудитория
- частный риелтор, который ведёт 20-200 клиентов и до 100 объектов;
- небольшое агентство (1-10 агентов и руководитель/админ).

### Задачи Пользователя
- Не терять клиентов и не забывать про звонки/показы.
- Видеть, на каком этапе каждая сделка, и сколько ожидаемого дохода в воронке.
- Хранить характеристики и медиа объектов в одном месте.
- Распределять задачи и видеть нагрузку.
- Анализировать свою работу: сколько закрыто, сколько потеряно, какая конверсия.

## 2. Роли

| Роль | Описание | Доступ |
| --- | --- | --- |
| `admin` | Руководитель/владелец агентства | Видит всех агентов, всех клиентов, объекты, сделки, задачи. Может назначать ответственных и менять роли. |
| `agent` | Рядовой риелтор | Видит свои клиенты, объекты, сделки, задачи. Может видеть общие объекты агентства, но не чужие сделки/клиенты. |

В MVP: роль зашита в `profiles.role`, переключается админом из UI или вручную в Supabase.

## 3. MVP Scope

### В MVP Входит
- Регистрация/логин по email и паролю через Supabase Auth.
- Профиль пользователя с ролью.
- Дашборд: количество сделок по статусам, задачи на сегодня, новые клиенты за 30 дней, график доходности.
- Клиенты: CRUD, поиск, фильтры (источник, статус, ответственный), карточка клиента с историей задач/сделок.
- Объекты недвижимости: CRUD, фильтры (тип, цена, район, статус), карточка объекта.
- Сделки: kanban-воронка по статусам, drag-and-drop между статусами, карточка сделки.
- Задачи: список с фильтрами, статусы, дедлайны, привязка к клиенту/сделке/объекту.
- Адаптивный UI, тёмная тема.
- Demo-данные через `seed.sql`.
- README с инструкцией.

### Намеренно Не Входит В MVP
- Календарь и интеграции с внешними календарями.
- Telegram/email-уведомления.
- Чат с клиентом, телефония, IP-телефония.
- Парсинг ЦИАН/Авито.
- Платежи, договоры, документы.
- Многоарендность (несколько агентств в одной БД).
- Сложная аналитика, прогнозы, ML.
- Мобильное приложение.

## 5. Пользовательские Сценарии

### Сценарий 1: Регистрация Нового Клиента
1. Агент заходит на `/clients`.
2. Нажимает "Добавить клиента".
3. Заполняет форму: имя, телефон, email, источник, бюджет, тип сделки, заметка.
4. После сохранения попадает на карточку клиента.
5. Может сразу создать связанную сделку или задачу.

### Сценарий 2: Перевод Сделки В "Завершено"
1. Агент открывает `/deals`.
2. Перетаскивает карточку сделки из "Договор" в "Завершено".
3. Вводит фактическую сумму и дату закрытия.
4. KPI на дашборде обновляются.

### Сценарий 3: Просмотр Дня
1. Агент заходит на `/dashboard`.
2. Видит блок "Задачи на сегодня".
3. Кликом по задаче открывает связанного клиента/сделку.

### Сценарий 4: Админ Назначает Клиента
1. Админ заходит в `/clients`.
2. Открывает клиента и меняет ответственного агента.
3. Клиент пропадает у предыдущего ответственного и появляется у нового.

## 7. Правила Доступа (Row Level Security)

### `profiles`
- `select`: любой авторизованный пользователь может читать профили (для отображения имён ответственных).
- `update`: пользователь может менять только свой профиль; `admin` — любой.

### `clients`, `properties`, `deals`, `tasks`
- `select`: `admin` видит всё; `agent` видит записи, где он `assigned_to` или `created_by`.
- `insert`: любой авторизованный; `created_by` автоматически = текущий пользователь.
- `update`/`delete`: владелец записи (`assigned_to` или `created_by`) или `admin`.

Объекты `properties` дополнительно: все агенты могут видеть активные объекты агентства (`status != archived`), потому что объекты — общий ресурс.

## 8. Состояния UI

Каждый список и карточка должны корректно отображать:
- `loading` — skeleton либо спиннер;
- `empty` — иллюстрация/иконка + кнопка "Создать";
- `error` — сообщение и кнопка "Повторить";
- `success` — нормальный контент.

Формы:
- inline-валидация через Zod;
- disabled state у кнопки во время сабмита;
- toast при успешном сохранении/ошибке.

## 9. Дашборд

Виджеты:
- Количество сделок по статусам (карточки с цифрами).
- График: сумма сделок по месяцам за последние 6 месяцев (`Recharts AreaChart` или `BarChart`).
- Конверсия: новых клиентов → выигранных сделок за 30 дней.
- Задачи на сегодня (топ 5).
- Последние добавленные клиенты (топ 5).

## 10. Технические Требования

- Next.js App Router, server components везде, где возможно.
- Запросы к Supabase из server components и server actions.
- TanStack Query — для интерактивных списков (фильтры, kanban).
- TanStack Table — для таблиц клиентов, объектов, задач.
- `@dnd-kit/core` — для kanban сделок.
- `Recharts` — графики.
- Тёмная тема через `next-themes` + Tailwind.
- ESLint + Prettier.
- Сборка через `next build` без ошибок типов.
